# P3 直前信頼度：レース選別に役立つ評価への再設計

作成日: 2026-10-27  
状態: 設計案 / 本番未適用  
対象: 通常 P3 の直前 LOCK（5・8・15点）。既存の予想・買い目・会計を評価する。

## 1. 解決する問題と評価の意味

現行の「5点はB、8点はB、15点はA」は点数群の平均成績を各レースへ付けている。同じ点数のレースを選び分けられず、個別信頼度としては採用しない。

新しい信頼度の対象は「このレースで、締切前に確定した P3 の買い目のどれかが、公式の3連単結果と一致する確率」。頭の的中確率、波乱度、点数群の平均、利益が出る確率とは区別する。

- ランクは個別レースの校正済み推定的中率を区分する。同点数内の相対順位を A と呼ぶ方式にはしない。
- 点数が増えれば的中範囲は広がり得るが、それだけで評価システムの有用性を証明したことにはしない。
- 採用には、5点同士・8点同士・15点同士で、事前評価の高い群ほど実際に当たることが必要。
- 的中率と回収率は分ける。回収率・平均投資額は検証報告に併記するが、的中信頼度から利益を保証しない。
- 私や TRUE が雰囲気で A/B を選ばない。保存済みの入力、固定した計算式、結果を見る前に決めた検証で決める。

## 2. 表示仕様

カードには P3 名の横に、直前のバッジを1個だけ置く。朝のランク行と独立した大きな信頼度枠は作らない。

表示の形（実測結果ではない）:

- 実証済み参考モデル: `🧠 P3［直前 参考A］`
- 既存の正式認定まで満たしたもの: `🧠 P3［直前 A］`

バッジを開くと次を表示する。

1. この直前買い目に対する推定的中率と点数。
2. 同じ予想世代・同じ点数の平均との比較。両方とも同じ学習期間を使う。
3. その予測帯の未使用期間における検証件数、的中数、実測的中率、区間、日数。
4. 評価に使った材料の説明を最大2件。モデルが示していない因果的な理由は作らない。
5. 評価時刻と、学習に使用した結果の最終日。

ランク境界は既存の意味を引き継ぐ設計案とする。S: 60%以上、A: 40%以上60%未満、B: 20%以上40%未満、C: 20%未満。入力は必ず校正済みの個別推定値とする。点数別平均をこの表へ入れて全レースへ配る処理は廃止する。

境界は自然法則ではなく表示上の区分であり、S/A が一定数出るように閾値や計算を調整しない。同一ランク内の違いは詳細の推定率で見られる。S は既存の追加証拠条件を満たすまで表示しない。証拠不足を下位ランクと誤表示せず、その帯は文字ランクを保留する。

## 3. 計算仕様

### 対象とラベル

- 単位: 1レース × LIVE × 実際の直前買い目集合。
- 正解 y: 公式結果のいずれかが集合内に存在すれば1、なければ0。
- 返還・不成立・結果未確定は別状態とし、0へ変換しない。初版は返還のない成立レースを対象にする。
- 予想世代、選定方式、モデル版、点数を混同しない。特殊固定8点は通常8点と別。
- 朝の点数・買い目ではなく LIVE の点数・買い目へ必ず結び付ける。

### 最初に比較する候補

| 候補 | 入力と計算 | 用途 |
|---|---|---|
| M0 | 同世代・同点数の過去平均。学習時の的中数 h、件数 n から (h+1)/(n+2) | 必ず比較する基準。個別ランクには使わない |
| M1 | 保存済み P3 120通り分布のうち、実際の買い目に対応する確率質量 q を合計。点数別に単調なロジスティック補正 | 最初の本命候補。少ない自由度で、q に識別力があるか確認 |
| M2 | M1 に、同点数での買い目選択効率を追加した小さな正則化モデル | M1 に差が出ない、または改善余地がある場合の別実験。新しい未使用期間で判定 |
| T1 | 当時保存された TRUE の6艇重みから、確定できた買い目の被覆指標を作る | 過去328件を活用する探索用候補。P3 の欠損スコアの代用として扱わない |

M1 の式は `p = sigmoid(a_N + b_N * logit(clip(q, 1e-6, 1-1e-6)))`、N は5/8/15、b_N >= 0。点数別に学習し、共有の傾きや別世代との混合は初版では行わない。実装時には補正器・正則化・実装版を実験計画に固定する。b_N=0 に近づき定数になった候補は、有用性検証を通らない限り出さない。

M2 の選択効率は `q / 同じ分布で上位N通りを選んだ場合の質量`。これは実際の買い目がそのモデルの有力な組み合わせをどれだけ押さえたかの指標であり、実測的中率ではない。

説明・後続研究のために、選んだ頭の質量、頭が入った条件下での2・3着の被覆、分布の散らばり、上位艇のスコア差、TRUE の被覆も保存する。ただし手作業で「頭が強いから+10点」と加算しない。相互に関連する量を独立証拠として二重加算しない。

TRUE の現在の重みは頭の予測を起点とする。そこから作る2・3着の重みを、そのまま校正済み3連単確率とは呼ばない。P3 とゴリが共通の TRUE 入力を使う場合、その一致を「独立した二つのAIが一致」として加点しない。

波乱度は5/8/15点の決定と検証の切り口に使う。「波乱度が低いほど的中信頼度が高い」という強制ルールは設けない。低波乱度群の的中率が低ければ、点数・買い目範囲・頭と相手の外れ方を分けて調べる。

## 4. 現在ある過去データの使い方

確認済みの再現対象は 2026-10-22〜26 の5日間、736レース。現在の選定式による買い目が一意に決まったのは328レース。

| 直前点数 | 全再現対象 | 買い目が一意 | 開発日に一意 | 固定検証日に一意 |
|---|---:|---:|---:|---:|
| 5 | 319 | 139 | 117 | 22 |
| 8 | 355 | 127 | 105 | 22 |
| 15 | 62 | 62 | 52 | 10 |
| 合計 | 736 | 328 | 274 | 54 |

- 736件には当時の P3 の6艇数値スコア・120通り分布が保存されていない。736件すべてを M1 の学習用完全データと数えない。
- 一意な328件でも、M1 の必須入力がそろっていることを意味しない。T1 は保存 TRUE 入力との結合を再確認したうえで別の探索として使う。
- 残りの買い目が不定なレースは、点数別成績の上下限として残す。結果に合う候補集合を後から選ばない。
- 「買い目は不定だが的中有無だけ判定できる行」だけを学習へ選ぶと、採否が結果に依存し得る。この抽出では学習しない。
- 一意な集合だけの分析でも、対象となった会場・波乱度・日付の偏りを報告し、全レースへそのまま一般化しない。
- 固定検証日は開発へ戻さない。10月23日の成績は既に確認されているため、新設計を選んだ後の未使用最終テストとは扱わない。
- 当時の入力が復元できないところへ現在の成績・現在の展示・結果を埋め込まない。

参照証拠: relay研究ブランチの `scripts/p3_5815_replay.py`、監査run 40437026720、Site の `docs/research-evidence/p3-5815-replay-20261027.json`。行証拠 SHA256 は `44f84e1015fa4473784d62bab3494417cd8cccedf8493b3d82a06c68aa5ff331`。

## 5. 有用性を判定する検証計画

確率の補正と、当たるレースを見分ける能力は別々に検証する。数字を実測平均へ近づけただけでは合格にしない。

1. 現行の固定日付分割を維持する。2026-09-29を基点に5日周期の5日目は HOLDOUT。HOLDOUT は学習へ再利用しない。
2. 学習は常に予測日の前日までに受領・確定した DEVELOPMENT の結果だけ。予測を発行してから後日結果を照合する。
3. 過去の開発日では日付順の前進検証で候補を選ぶ。ランダムにレースを分けて、同日の前半と後半を学習・検証へ混ぜない。
4. 候補を決めて式・入力・閾値・対象・集計方法を凍結し、その後の未使用 HOLDOUT を最終評価に使う。
5. 5/8/15点それぞれに M0 と比較する。全点数を混ぜた成績で、どれかの群の失敗を隠さない。

初回公開判定の具体的な基準案:

- 各点数について、未使用 HOLDOUT 10日以上かつ200件以上。これは検定力を保証する件数ではなく最低条件。足りない点数群だけ保留する。
- M0 に対する Brier 損失差が改善し、日単位で対応をそろえたブロック再標本化の95%区間でも改善が残る。
- 学習時に固定した高評価群（学習予測分布の上位25%境界。境界の同点をまとめて含め、日ごとに無理に25%を選ばない）について、同点数の全検証群との差が5パーセントポイント以上、日ブロック95%区間の下端が0を上回る。高評価群は50件以上、5日以上。
- 推定値を既存の S/A/B/C 境界で区分し、表示する各帯に100件以上、5日以上の独立検証結果を要求する。帯内の平均予測と実測の差が5ポイント以内で、日ブロック区間を含めた誤差が±10ポイント以内。実測率区間の全幅は20ポイント以内。
- 十分な件数のある帯で実測的中率の順序が逆転した場合はそのまま表示しない。式・帯を直すなら新しい計画・新しい未使用期間で再評価する。
- AUC、logloss、日別・会場別・波乱度別の誤差、回収率、欠損率、対象率も報告する。AUCだけで合格にはしない。
- 正式Sは既存の300件・30日以上、実測60%以上、Wilson下端50%超、その他の認定条件を追加で満たす。
- 最低件数、5ポイント改善、各許容幅は今回提案する運用基準。満たせば必ず将来も当たるという統計的保証ではない。

再標本化は日を単位とし、同じ日の候補とM0を一緒に引く。反復数・seed・区間計算法を計画へ固定する。例として10,000反復、seed=20261027、両側percentile区間を初版の候補にする。日数が少ないと区間自体が不安定になるため、日数条件を省略しない。

計画の終期を検証結果を見る前に固定する。終期時点で件数不足なら保留とし、「たまたま合格した日」で打ち切らない。最終テストを見た後にM2へ切り替え、同じ期間を未使用テストとして再利用しない。

## 6. 保存と更新

LIVE LOCK 時に結果のない評価行を追記し、NIGHT に公式結果を別レコードとして結合する。ハッシュだけで元の数値が消える問題を防ぐ。

保存する最小契約:

- race_id / JST日付 / LIVE / deadline / prediction_locked_at / captured_at
- predictor fingerprint / selection policyと版 / confidence feature schemaと版
- 入力snapshot SHA / ソース版 / TRUEモデル版・SHA
- 直前買い目全件とそのSHA / 点数 / 波乱度
- P3 6艇スコア、120通り分布、raw_set_probability、各SHA
- TRUE 6艇重みと取得時刻・由来。欠損はnullと理由を保存
- 計算した特徴量と入力の欠損フラグ
- 推定値 / model version / training cutoff / training manifest SHA / baseline値
- grade / grade basis / validation report SHA / issued_at / 発行状態
- 結果の別レコードに official result / revision / received_at / source SHA / HIT・MISS・VOID・PENDING

毎夜確定結果を追記し、承認された学習手順に従い前日までの DEVELOPMENT を用いて次の日用の補正を更新する。最初に「この更新手順そのもの」を前進検証する。HOLDOUT を見ながら毎日パラメータや特徴量を選び直す方式にはしない。

- 新しい係数には版と学習締切を付ける。翌日の新しい LIVE LOCK から使用する。
- 発行済みランクと買い目を後日の学習で書き換えない。
- 結果訂正は履歴を残して統計を再集計する。過去の発行予測は不変。
- 学習窓は現行の最大180日を初期候補とし、別世代は混ぜない。
- 入力不正、時刻不正、世代不一致、未検証範囲では個別ランクを発行しない。点数群平均へのフォールバックは禁止。
- 同じ評価手順の更新と、特徴量・選定方式を変える改版を分ける。改版には新しい未使用検証期間が必要。
- 更新後の劣化は事前に固定した期間で再評価し、基準を外れた点数群の新規ランクを停止する。停止をB/Cへ置き換えない。

## 7. 実装の順番と完了条件

| 順番 | 実装箇所・作業 | 完了条件 |
|---|---|---|
| 1 | producer の confidence context / daily evidence とアーカイブ保存 | LIVEの特徴量が締切前に保存され、日付が変わっても再現できる。既存買い目が一致 |
| 2 | research の点数別 M0/M1、T1探索、日付順検証、結果表 | 結果を見ずに作った個別評価と後日の公式結果を照合できる。平均だけのモデルは不合格になる |
| 3 | immutable な confidence receipt とモデル版管理 | exact LIVE set、時刻、世代、学習締切、証拠が一致し、過去発行を更新しない |
| 4 | Site の live-rank / badge / 詳細表示 | P3横に直前1個。点数群平均由来の一律B/A表示を撤去。検証を通った帯だけ個別ランクを表示 |
| 5 | NIGHT更新、監視、改版手順、憲法差分 | 更新対象は次のLIVE。証拠・不足理由・停止状態を追える |

既存ソースで主に扱う場所:
- boat-brain-lab: `confidence_context_v2.py`、`confidence_daily_evidence_v1.py`、`confidence_calibration_research_v1.py`、`confidence_reliability_diagnostics_v1.py`。
- Site: `lib/g11-p3-confidence-updates.ts`、`lib/g11-p3-live-rank.ts`、`lib/g11-p3-historical-reference.ts`、`components/g11-p3-card-confidence.tsx`。
- 憲法付則B: 点数別平均による初期ランク、および POINT_GROUP への降格処理を、個別評価の許可根拠から外す。これは提案差分であり、この設計書だけでは憲法を改定しない。

必要な検証は、締切後の評価拒否、結果入力混入拒否、世代・点数・買い目の不一致拒否、未来結果による学習拒否、HOLDOUT混入拒否、未知値とゼロの区別、既発行LOCK不変、点数群定数モデルの有用性不合格、日付をまたぐ再現、表示バッジ1個を中心にする。

完了の定義は「画面にA/Bが出た」ではなく、「未使用の後の日付でも、同点数の高評価群に実測差があり、その根拠を画面から確認できる」。

現時点で完了したのはこの設計。個別評価モデルの有効性検証、憲法の再改定、Siteの置き換えは未実施。公開日を推測で約束しない。
